Problem Formulation

Problem formulation in Artificial Intelligence is the process of precisely defining a problem in such a way that it can be solved by an intelligent agent. It involves identifying the initial state, the possible actions, the transition model, the goal test, and the path cost. A problem is well-formulated only when these components are clearly described.

The main purpose is to convert a vague, real-world situation into a well-defined structure that an AI system can handle using search or decision-making techniques.

State Space

The state space is a conceptual structure that consists of all possible states of a system and the legal moves from one state to another. In AI, problems are modeled as navigating through a space of possible configurations (states) using actions (operators) to reach a desired goal.

Example: In a chess game, each board configuration is a state; each move is an operator.

Components of State Space

  • Initial State: Where the search begins.
  • State Space: All states reachable through actions.
  • Operators (Actions): Transform one state to another.
  • Goal State/Test: Check if the current state is a goal.
  • Path Cost: Cost associated with the path taken.

Uninformed Search Algorithms

  • These algorithms are given no information about the problem other than its definition.
  • They are also called blind search algorithms. The strategies have no additional information about states beyond that provided in the problem definition.
  • All they can do is generate successors and distinguish a goal state from a non-goal state. All search strategies are distinguished by the order in which nodes are expanded.
  • Although some of these algorithms can solve any solvable problem, none of them can do so efficiently.
  • Examples: Depth First Search, Breadth First Search, Depth Limited Search, Iterative Deepening Depth First Search, Bidirectional Search.

Key features of uninformed search algorithms

  • Systematic exploration: explores the search space systematically, either by expanding all children of a node (e.g. BFS) or by exploring as deep as possible in a single path before backtracking (e.g. DFS).
  • No heuristics: does not use additional information, such as heuristics or cost estimates, to guide the search.
  • Blind search: does not consider the cost of reaching the goal or the likelihood of finding a solution.
  • Simple to implement: easy to understand, a good starting point for more complex algorithms.
  • Inefficient in complex problems: with large search spaces, the number of states explored increases exponentially.

Depth First Search (DFS)

  • DFS always expands the deepest node in the current frontier of the search tree.
  • The search proceeds immediately to the deepest level of the search tree, where the nodes have no successors. As those nodes are expanded, they are dropped from the frontier, so the search "backs up" to the next deepest node that still has unexplored successors.
  • DFS uses a stack (LIFO queue) for the frontier. The most recently generated node is chosen for expansion, which must be the deepest unexpanded node.

Advantages

  • DFS requires very little memory as it only needs to store a stack of the nodes on the path from the root node to the current node.
  • It takes less time to reach the goal node than BFS (if it traverses in the right path).

Disadvantages

  • Many states may keep re-occurring, and there is no guarantee of finding the solution.
  • DFS goes deep down and sometimes it may go down an infinite or invalid path.

Algorithm: iterative version

  1. Push the start node onto the stack.
  2. While the stack is not empty: pop the top node; if it is not visited, mark it visited and process (print) it; push all its unvisited neighbors onto the stack.
  3. Stop.

The basic steps of DFS on a graph

  1. Start with any unvisited node, visit it, and consider it as the current node.
  2. Search for an unvisited neighbour of the current node, visit it, and update it as the current node.
  3. If all the neighbours of the current node are visited, then backtrack to its predecessor (or parent) and update that predecessor as the new current node.
  4. Repeat steps 2 and 3 until all nodes in the graph are visited.
  5. If there are still unvisited nodes present in the graph, repeat steps 1 to 4.

Breadth First Search (BFS)

  • BFS is an algorithm used to traverse or search through tree or graph data structures.
  • It begins at the root of the tree (or an arbitrary node in a graph) and explores all neighboring nodes at the current depth before moving to nodes at the next depth level.
  • BFS is implemented using a queue (FIFO).
  • It visits the "shallowest node first", always choosing the shallower branch until it finds the solution or exhausts all nodes.

Algorithm

  1. Declare a queue and insert the starting vertex.
  2. Initialize a visited array and mark the starting vertex as visited.
  3. Repeat until the queue is empty: remove the first vertex from the queue; mark this vertex as visited; add all unvisited neighbors of this vertex to the queue.

Advantages

  • BFS guarantees a solution if one exists.
  • When multiple solutions are possible, BFS finds the one with the fewest steps.

Disadvantages

  • It consumes a lot of memory because each tree level must be stored to generate the next.
  • BFS can be time-consuming if the solution is located far from the root.

Depth Limited Search (DLS)

Depth Limited Search (DLS) is a modification of DFS that addresses DFS's issue with infinite state spaces. It works by setting a predetermined depth limit, denoted as ℓ. Any nodes at this depth ℓ are treated as if they have no successors, effectively preventing the search from going infinitely deep.

Key characteristics

  • Solves the infinite-path problem: by imposing a depth limit, DLS guarantees termination, unlike unbounded DFS.
  • Special case of DFS: a variant of DFS where the search is artificially constrained by depth.
  • Optimal depth limit: the diameter of the state space can give a better depth limit, but it is often unknown until the problem is solved.
  • Failure conditions: standard failure means no solution exists; cutoff failure means no solution was found within the specified depth limit.
  • LIFO stack for the frontier, like DFS: the deepest unexpanded node is expanded next.

Advantages

  • Efficiency: more efficient in time and memory than unbounded DFS.
  • Guaranteed solution (if it exists within the limit): DLS will find it in a finite amount of time.

Disadvantages

  • Incompleteness: it may not find a solution if the shallowest solution is beyond the set depth limit.
  • Suboptimality: it may not find the optimal solution if multiple solutions exist, especially if a suboptimal solution is found at a shallower depth.

DLS properties

  • b = branching factor, ℓ = depth limit, d = shallowest solution depth. Number of nodes in the tree = b0 + b1 + b2 + ... + bℓ = O(bℓ). DFS is a special case of DLS with ℓ = ∞.
  • Time complexity: O(bℓ).
  • Space complexity: only a single path from the root is stored (siblings on the path), so O(bℓ).
  • Completeness: incomplete if ℓ < d (the shallowest goal is beyond the depth limit).
  • Optimal: non-optimal if ℓ > d.

Example

Tree: S has children A, B. A has C, D. B has I, J. C has E, F. D has G. I has H. Goal state J.

The path to goal state J is: S, A, C, D, B, I, J.

Iterative Deepening Depth-First Search (IDDFS / IDS)

IDDFS is a general strategy, often used with depth-first tree search, that finds the best depth limit. It gradually increases the limit (0, 1, 2, and so on) until a goal is found, which happens when the depth limit reaches d, the depth of the shallowest goal node.

IDDFS uses a LIFO stack for the frontier, just like DFS. In general it is the preferred uninformed search method when the search space is large and the depth of the solution is unknown.

Advantages

  • Useful when the search space is large and the depth of the goal node is unknown.
  • Combines the benefits of BFS and DFS in terms of fast search and memory efficiency.
  • Like DFS, its memory requirements are modest: O(bd).
  • Like BFS, it is complete when the branching factor is finite and optimal when the path cost is a non-decreasing function of the depth of the node.

Disadvantages

  • The main drawback of IDDFS is that it repeats all the work of the previous phase.

IDDFS properties

  • b = branching factor, d = shallowest solution depth. Number of nodes = (d)b0 + (d-1)b1 + (d-2)b2 + ... + (3)bd-2 + (2)bd-1 + (1)bd = O(bd).
  • Time complexity: O(bd).
  • Space complexity: only a single path from the root node is stored, so O(bd).
  • Completeness: complete if the branching factor b is finite.
  • Optimal: optimal if path cost is a non-decreasing function of the depth of the node.

Example

Tree: A has B, C. B has D, E. C has F, G (goal). D has H, I. F has K.

Uniform Cost Search (UCS)

UCS is a graph/tree search algorithm used in Artificial Intelligence to find the optimal (least-cost) path from a start node to a goal node. UCS is a variant of Dijkstra's Algorithm and works by always expanding the node with the lowest total cost. It uses a priority queue.

How UCS works

  1. Start from the initial node and assign it a cost of 0.
  2. Expand the node with the lowest cost.
  3. Update the costs of neighboring nodes.
  4. Repeat this process until the goal node is reached.
  5. The path found is guaranteed to be the shortest (least-cost) path.

Example: simple tree with costs

A → B = 4, A → C = 2, B → D = 5, B → E = 1, C → F = 3, E → G = 2. Goal: find the least-cost path from A to G.

         A
      4 / \ 2
       B     C
    5/  \1    \3
    D    E     F
         |2
         G
StepAction
1Start at A, cost = 0.
2Expand A, add B (cost 4) and C (cost 2) to the priority queue.
3Expand C (cheaper cost = 2), add F (cost 5).
4Expand B (cost = 4), add D (cost 9) and E (cost 5).
5Expand E (cheaper cost = 5), add G (cost 7).
6Goal G is reached with total cost = 7.

Final path: A → B → E → G with cost 7.

Pros of UCS

  1. Guaranteed optimal solution: always finds the least-cost path, ideal for pathfinding problems where cost matters.
  2. Works with different costs: unlike BFS (which assumes equal edge cost), UCS handles variable costs.
  3. Complete algorithm: if a solution exists, UCS will find it.
  4. Useful for weighted graphs: effective in real-world applications like route planning (e.g. GPS navigation).

Cons of UCS

  1. Slow for large graphs: explores many nodes before reaching the goal.
  2. High memory usage: stores all paths in a priority queue.
  3. Traps in infinite loops: if the graph has negative cycles (loops with decreasing cost), UCS may run indefinitely.
  4. Not always fastest: can be slower than A* search, which uses heuristics to speed up the search.

Informed Search Algorithms

These algorithms employ strategies that discern whether one non-goal state holds more promise than another. They are also known as heuristic search strategies and can perform effectively with guidance on where to seek solutions.

Examples include Hill Climbing, Best First Search, A* and AO* Algorithms, Constraint Satisfaction, Means-Ends Analysis, Minimax Search, and Alpha-Beta Cutoffs.

Key features of informed search algorithms

  • Use of heuristics: use heuristics, or additional information, to direct the search process and prioritize which nodes to expand.
  • More efficient: more efficient than uninformed search (BFS, DFS) by avoiding unlikely paths and concentrating on more promising ones.
  • Goal-directed: they aim to find a solution to a specific problem.
  • Cost-based: often use cost-based estimates to evaluate nodes, such as the estimated cost to reach the goal or the cost of a particular path.
  • Prioritization: prioritize which nodes to expand based on available additional information.
  • Optimality: may guarantee an optimal solution if the heuristics used are admissible (never overestimating the actual cost) and consistent.

Greedy Best First Search

  • Best-first search uses the concept of a priority queue and heuristic search. To search the graph space, the method uses two lists for tracking the traversal.
  • An OPEN list keeps track of the current "immediate" nodes available for traversal and a CLOSED list keeps track of the nodes already traversed.
  • We expand the node which is closest to the goal node, and the closeness is estimated by the heuristic function.

Evaluation function (Greedy Best-First): f(n) = h(n), where h(n) is the estimated cost from node n to the goal.

Algorithm

  1. Create 2 empty lists: OPEN and CLOSED.
  2. Start from the initial node (say N) and put it in the "ordered" OPEN list.
  3. Repeat the next steps until the GOAL node is reached:
    1. If the OPEN list is empty, then EXIT the loop returning "False".
    2. Select the first/top node (say N) in the OPEN list and move it to the CLOSED list. Also capture the information of the parent node.
    3. If N is a GOAL node, then move the node to the Closed list and exit the loop returning "True". The solution can be found by backtracking the path.
    4. If N is not the GOAL node, expand node N to generate the "immediate" next nodes linked to node N and add all those to the OPEN list.
    5. Reorder the nodes in the OPEN list in ascending order according to the evaluation function.

A* Search Algorithm

  • Informed search technique (heuristic search): A* uses heuristic information to guide the search more efficiently than uninformed methods, choosing the most promising paths to explore.
  • Heuristic value usage: a heuristic function estimates the cost from the current node to the goal, so it can prioritize nodes more likely to lead to the solution.
  • h(n) and g(n): h(n) estimates the cost to reach the goal from node n, while g(n) is the exact cost to reach node n from the start. Combining them balances exploration and exploitation.
  • Finding the shortest path: A* aims to find the shortest path by exploring nodes that minimize the total estimated cost.
  • Performance: fast and optimal when the heuristic is admissible (never overestimates the true cost).
  • Complexity: comparable to BFS, O(V + E), where V is the number of vertices and E the number of edges. It is also written as O(bd), where b is the branching factor and d the depth of the shallowest goal node.

Estimated cost function: f(n) = g(n) + h(n)

n: the current endpoint node on the path
g(n): accumulated cost from the starting node to node n
h(n): heuristic prediction of the lowest cost from node n to the destination
f(n): total estimated cost of the path through n

Algorithm

A* maintains two lists. OPEN contains nodes that have been evaluated by the heuristic function but not yet expanded into successors. CLOSED contains nodes that have already been visited.

StepAction
Step-01Define a list OPEN. Initially, OPEN consists solely of a single node, the start node S.
Step-02If the list is empty, return failure and exit.
Step-03Remove node n with the smallest value of f(n) from OPEN and move it to list CLOSED. If node n is a goal state, return success and exit.
Step-04Expand node n.
Step-05If any successor to n is the goal node, return success and the solution by tracing the path from goal node to S. Otherwise, go to Step-06.
Step-06For each successor node, apply the evaluation function f to the node. If the node has not been in either list, add it to OPEN.
Step-07Go back to Step-02.

Heuristic Function

A heuristic function maps from problem state descriptions to measures of desirability, usually represented as numbers. The aspects of the problem state that are considered, how those aspects are evaluated, and the weights given to individual aspects are chosen so that the value of the heuristic function at a given node gives as good an estimate as possible of whether that node is on the desired path to a solution.

Well designed heuristic functions can play an important part in efficiently guiding a search process toward a solution.

Admissible Heuristic Function h(n)

A heuristic function is admissible if it never overestimates the cost of reaching the goal.

h(n) ≤ h*(n)

Here h(n) is the heuristic cost and h*(n) is the actual cost to reach the goal. So the heuristic cost should be less than or equal to the actual cost.

Example (admissible)

Edges: A-B = 1, A-C = 1, A-D = 1, B-E = 3, E-F = 5, F-G = 2 (goal G). Heuristic: H(B) = 3, H(C) = 4, H(D) = 5, H(E) = 2, H(F) = 3. F(n) = H(n) + G(n), cost = heuristic cost + actual cost.

  • Actual cost from A to G = 1 + 3 + 5 + 2 = 11.
  • H(B) = 3, so h(n) = 3 and h*(n) = 11. Since h(n) ≤ h*(n), i.e. 3 ≤ 11, the heuristic is ADMISSIBLE.

Non-Admissible Heuristic Function h(n)

A non-admissible heuristic may overestimate the cost of reaching the goal.

h(n) > h*(n)

So the heuristic cost may be greater than the actual cost. Total cost = search cost + path cost.

Example (non-admissible)

Edges: A-B = 1, A-C = 1, A-D = 1, D-G = 3, B-E = 3, E-F = 5, F-G = 2 (goal G). Heuristic: H(D) = 5.

  • Actual cost from A to G (via D) = 1 + 3 = 4.
  • H(D) = 5, so h(n) = 5 and h*(n) = 4. The condition h(n) ≤ h*(n) becomes 5 ≤ 4, which is false, so the heuristic is NON-ADMISSIBLE.

Consistency

In A* search, a heuristic function h(n) is called consistent if, for every node n and its successor n', the estimated cost from n to the goal is less than or equal to the actual cost of moving from n to n' plus the estimated cost from n' to the goal.

h(n) ≤ c(n, n') + h(n')

where h(n) is the estimated cost from n to the goal, c(n, n') is the actual cost of moving from n to n', and h(n') is the estimated cost from n' to the goal.

  • This condition is also known as the monotonicity condition or triangle inequality.
  • A consistent heuristic ensures that f(n) = g(n) + h(n) does not decrease along a path in A*. So once a node is expanded, its optimal path cost does not need to be reconsidered.
  • A consistent heuristic is always admissible, i.e. it never overestimates the actual minimum cost to reach the goal.
  • Thus consistency helps A* find an optimal solution efficiently and prevents unnecessary re-expansion of nodes.

Local Search

  • Hill climbing: repeatedly move to the best neighbour; stops when no neighbour is better. Problems: local maxima, plateaus, ridges.
  • Simulated annealing: sometimes accepts a worse move with probability eΔE/T. Temperature T is lowered slowly, so early on it explores and later it settles. This helps escape local maxima.
  • Local search uses little memory and suits optimisation problems where the path does not matter (N-queens, scheduling).

Adversarial Search

  • Minimax: two players, MAX tries to maximise and MIN to minimise the utility. Values are backed up from the leaves of the game tree.
  • Alpha-beta pruning: alpha = best value MAX can guarantee so far, beta = best value for MIN. Prune a branch when alpha ≥ beta. Same result as minimax, fewer nodes.
  • With best move ordering, alpha-beta examines about O(bm/2) nodes instead of O(bm).

Constraint Satisfaction Problems

A CSP has variables, domains and constraints. A solution assigns a value to every variable without breaking any constraint.

Example: map colouring. Variables = regions, domain = {red, green, blue}, constraint = neighbouring regions have different colours.

Backtracking: assign one variable at a time, check constraints, undo (backtrack) when a constraint fails.
